このツールの特性

RSS の新着を集め、本文取得と Gemini 分析を経て Gmail でダイジェスト配信する一方向バッチパイプラインです。設定の中心は src/settings.ts、秘密情報は環境変数です。

① 処理の流れ（main の 5 ステップ）

  1. Step 1 RSS 取得 複数フィードを窓（lookback）内でミックス。サンプル実行時はモック JSON も可。
  2. Step 2 Jina Reader 記事 URL の本文を並列取得（設定で並列数・タイムアウト等）。
  3. Step 3–4 Gemini URL ごと要約（Flash 等）→ 全体トレンド分析。モデル名は settings で指定。
  4. Step 5 Gmail 送信 HTML/テキストのダイジェストメールを SMTP で配信。
  5. 任意 配信済み URL 記録 有効時は未配信のみ処理し、成功後に URL を永続化して重複配信を抑制。

③ 設計上の特性（ざっくり一覧）

単発ジョブ型

常駐サーバではなく、起動したら最後まで流して終了します。GitHub Actions の定期実行などに向いています。

設定の単一窓口

ビジネス寄りの定数は settings.ts に集約。環境依存の鍵は config（zod 検証）側です。

エラー文言の意図

UserFacingError は受講生向けメッセージとして扱われ、それ以外は内部エラー扱いでログに出ます。

観測可能性

GitHub Actions 上ではジョブサマリーに件数・失敗理由などを書き出し、運用時の把握を補助します。
